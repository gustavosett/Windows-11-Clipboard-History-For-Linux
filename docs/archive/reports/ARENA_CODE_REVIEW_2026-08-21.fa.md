## Windows 11 Style Clipboard History Manager

**تاریخ بازبینی:** ۲۰۲۶-۰۸-۲۱

**روش:** بازبینی موشکافانه دستی (code walkthrough) به‌همراه بازتولید عملی برخی گیت‌ها (`npm ci`) و تحلیل زنجیره تأمین.

> یا علی مدد. این بازبینی به‌صورت مستقل انجام شده و دیدگاه‌ها صرفاً مبتنی بر محتوای مخزن در زمان بررسی است.

## ۱) تحلیل معماری و ساختار

### تصویر کلی
پروژه یک **مدیر تاریخچه کلیپ‌بورد دسکتاپ لینوکس** (Wayland و X11) با الهام از Win+V ویندوز ۱۱ است. پشته فنی به‌درستی انتخاب شده:

| لایه | انتخاب | ارزیابی |
|---|---|---|
| UI | React 19 + TypeScript + Tailwind 4 | مدرن، نوع‌ایمن |
| هسته | Rust + Tauri v2 | سبک، ایمن حافظه |
| کلیپ‌بورد | arboard + `wl-copy`/`xclip` | چندسکویی برای Wayland/X11 |
| مانیتورینگ | رویدادمحور (XFixes / `wl-paste --watch`) + polling تطبیقی | بهینه و مقیاس‌پذیر |
| ماندگاری | SQLite (WAL) + رمزنگاری ChaCha20-Poly1305 | حرفه‌ای |
| مدیریت کلید | فایل `0600` **یا** Secret Service | انعطاف‌پذیر و fail-closed |
| ورودی | uinput (Wayland) / XTest (X11) با **paste ticket** | امن و هوشمند |
| محلی‌سازی | فارسی/انگلیسی با فونت همراه (Vazirmatn) | آفلاین کامل |

### سازمان‌دهی فایل‌ها — امتیاز برجسته
- **جداسازی ماژول‌های Rust بر اساس نگرانی واحد (SRP):** هر فایل `src-tauri/src/*.rs` فقط یک مسئولیت دارد (رمزنگاری، SSRF، سیاست شبکه، شبیه‌سازی ورودی، حریم خصوصی، پنجره، ...). این الگو تحسین‌برانگیز است.
- **فرانت‌اند پاک:** جدا بودن `hooks/`، `components/`، `services/`، `utils/`، `i18n/` و `types/`.
- **مستندات معماری به‌صورت ADR (Architecture Decision Records):** ۸ رکورد تصمیم معماری با شماره (SQLite، تزریق paste، SSRF، رمزنگاری، زنجیره تأمین، کلید، صفحه‌بندی IPC، ACL پنجره). این یک **نشانه بلوغ** مهندسی است.

### انسجام معماری
معماری «عملیات شبکه‌محور در Rust، نه در webview» کاملاً منسجم است. مثال بارز: اعتبارسنجی URL برای باز کردن لینک‌ها (`open_safe_url`) در Rust انجام می‌شود نه TypeScript، و `net_policy.rs` به‌عنوان «منبع واحد حقیقت» برای بلوک IPها در هر دو مسیر SSRF و URL بازکنی استفاده می‌شود. این از «فرسایش» (drift) دفاع‌های امنیتی جلوگیری می‌کند — طراحی درجه‌یک.

## ۲) بررسی کیفیت کد (Code Quality)

### نکات مثبت
- **SOLID و Clean Code:** ماژول‌های تک‌مسئولیت، وابستگی‌های صریح، نام‌گذاری معنادار. تابع `consume_paste_ticket` با fail-closed منطق بلیت را دقیق پیاده می‌کند.
- **مشروح‌بودن توضیحات (doc comments):** تقریباً همه ماژول‌های حساس دارای مستندات سراسری فارسی+انگلیسی هستند که «چرا» (why) را توضیح می‌دهند، نه فقط «چه» (what).
- **ضدگام‌ها (anti-pattern) کمتر:** پردازش URL بدون shell، پاک‌کردن کلید در حافظه با `zeroize`، عدم دنبال‌کردن redirectها.
- **پوشش تست:** ۱۳ فایل تست فرانت‌اند + تست‌های Rust گسترده (شامل تست‌های منفی امنیتی: SSRF، بلیت paste، IPهای ممنوع).
- **ابزارهای کیفی:** ESLint نوع‌آگاه، `tsc`، Prettier، `cargo clippy -D warnings`، `cargo fmt`، گیت‌هوک‌ها (pre-commit/commit-msg).

### یافته‌های منفی و قابل‌بازتولید 🔴
1. **قفل وابستگی ناهمگام (باگ واقعی):** در `package.json` وابستگی `@playwright/test` اعلام شده، اما در `package-lock.json` **به‌طور کامل وجود ندارد**. نتیجه: `npm ci` روی یک checkout تمیز **شکست می‌خورد** (با پیام «Missing: @playwright/test@1.62.1 from lock file»). ازآنجاکه هم CI و هم `Dockerfile` از `npm ci` استفاده می‌کنند، این گیت در عمل نصب تمیز و CI را می‌شکند. **راه‌حل:** اجرای `npm install` و کامیت مجدد `package-lock.json`.
2. **تاریخچه گیت تک-کامیت:** فقط یک commit (merge) در شاخه دیده می‌شود؛ دنبال‌کردن تاریخچه تغییرات و نگارش غیرممکن است. برای ردیابی رگرسیون بهتر است تاریخچه granular نگهداری شود.
3. **کارشناس نمی‌تواند بیلد Rust را مستقل تأیید کند** (ابزار cargo/rustc در محیط نصب نیست)؛ بنابراین ادعای کیفیت Rust مبتنی بر بازبینی کد است، نه اجرای `cargo audit`/`clippy`.

## ۳) بررسی امنیت و شبکه

### این پروژه به‌طور غیرعادی «امنیت‌محور» است — از بهترین‌هایی که دیده‌ام:

| لایه دفاع | پیاده‌سازی | ارزیابی |
|---|---|---|
| رمزنگاری در حالت سکون | ChaCha20-Poly1305 روی ستون‌های متنی و تصاویر | ✅ عالی |
| مدیریت کلید | فایل `0600` یا Secret Service، راستی‌آزمایی با نشانگر، fail-closed | ✅ عالی |
| CSP | `script-src 'self'`، `font-src 'self'`، `withGlobalTauri:false` | ✅ عالی |
| SSRF | HTTPS-only + allowlist میزبان + DNS pinning + بدون redirect + بلوک IPهای خصوصی/لینک-محلی/متداتا | ✅ عالی |
| تزریق ورودی | **بلیت یک‌بارمصرف ۵ ثانیه‌ای** تا webview نتواند خودسرانه Ctrl+V بزند | ✅ عالی |
| حریم خصوصی | فیلتر اسرار (کلید، JWT، token، password=)، پرش از مدیر رمز، پرش از پنجره ناشناس (X11) | ✅ عالی |
| زنجیره تأمین | `cargo audit`/`cargo deny`/`npm audit` مسدودکننده در CI، SHA پینشده اکشن‌ها، SBOM و SLSA | ✅ عالی |
| توزیع | بررسی الزامی SHA256SUMS در نصب‌کننده + GPG اختیاری | ✅ عالی |
| محدودسازی | پروفایل AppArmor (حالت complain به‌صورت پیش‌فرض) | ✅ خوب |

### نقاط ضعف/ملاحظات (نه لزوماً باگ)
1. **قدرت ذاتی `/dev/uinput`:** برای شبیه‌سازی Ctrl+V به دستگاه ورودی مجازی نیاز است؛ خود پروژه صادقانه اعلام می‌کند «باینری را مانند یک دستگاه ورودی قابل‌اعتماد بپذیرید». این یک محدودیت ذات معماری است نه خطا. پروفایل AppArmor در حالت complain ارسال می‌شود، نه enforce — برای امنیت کامل باید فعال شود.
2. **کلید `history.key` کنار دیتابیس:** با وجود `0600`، اگر هر دو در یک پارتیشن/تصویر باشند، حملات آفلاین ساده‌تر می‌شوند. گزینه Secret Service بهتر است (پیش‌فرض نیست). پروژه این محدودیت را شفاف بیان کرده است.
3. **پرش از مدیر رمز فقط روی X11:** در Wayland، کامپوزیتور اپلیکیشن فوکوس‌شده را افشا نمی‌کند؛ پروژه صادقانه این را مستند کرده (راه‌حل: فیلتر اسرار روشن بماند).
4. **پروتکل `mailto` در `open_safe_url`:** مجاز است ولی کنترل‌کاراکتر و طول بررسی می‌شود؛ ریسک پایین است ولی خنثی‌سازی پروتکل همیشه باید به‌روز بماند.
5. **احراز هویت/مجوز:** پروژه یک اپ دسکتاپ محلی است و «احراز هویت» سرور ندارد؛ به‌جایش از مجوزگذاری پنجره (`window_policy` deny-by-default) و بلیت paste استفاده می‌کند — رویکرد درست برای این مدل.

> 🔒 نکته منفی کلیدی همین یک مورد است: **`@playwright/test` در lockfile نیست** — این بیشتر یک مشکل زنجیره ساخت/CI است تا آسیب‌پذیری، اما «امنیت ساخت» را خدشه‌دار می‌کند چون CI قابل‌بازتولید نیست.

## ۶) آمادگی انتشار به‌صورت .deb / .rpm / .AppImage / Flatpak

**پاسخ: بله، این پروژه از نظر ساختار کاملاً برای انتشار این فرمت‌ها آماده است — و به‌طرز چشمگیری این کار را درست انجام داده.**

| فرمت | وضعیت | توضیح |
|---|---|---|
| `.deb` | ✅ آماده و قابل‌ساخت | `targets: ["deb"]`، فایل‌های `debian/` کامل، اسکریپت postinst برای udev/uaccess، `lintian` پشتیبانی می‌شود |
| `.rpm` | ✅ آماده | spec فایل کامل + وابستگی‌ها (webkit2gtk4.1، gtk3، appindicator) |
| `.AppImage` | ✅ آماده | در `bundle.targets` فعال است؛ `IS_APPIMAGE` برای workaround WebKit |
| Flatpak | ✅ آماده (با محدودیت آگاهانه) | manifest + metainfo + build.sh کامل؛ **اما** سیاست Flathub `/dev/uinput` را نمی‌دهد، پس paste شبیه‌سازی‌شده در Flatpak در دسترس نیست (پروژه صادقانه این را مستند کرده) |
| AUR (بونوس) | ✅ | PKGBUILD و install موجود است |

### موانع کوچک پیش از انتشار «رسمی»
1. **رفع `package-lock.json`** (ناهمگام با `@playwright/test`) — بدون آن CI/نصب تمیز می‌شکند.
2. **ایمیل ساختگی در `debian/control`** را به ایمیل واقعی تغییر دهید (الزام لینتیان).
3. فعال‌سازی پروفایل AppArmor در حالت enforce برای ارسال امن‌تر (اختیاری اما پیشنهادی).
4. استفاده از Secret Service به‌جای کلید فایل برای محافظت قوی‌تر در حالت سکون (اختیاری).
